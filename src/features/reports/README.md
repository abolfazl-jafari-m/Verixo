# Reports data contract

Current state-management update (2026-10-25): OrdersProvider supplies an isolated Zustand store; ReportProvider scopes a Zustand filter store. Financial reports remain derived, never persisted. State/migration/hydration tests are now included in the reports Vitest project; historical verification notes below may describe previously removed tests.

The `/[locale]/reports` route composes report sections and reuses the global local-order provider. All summaries, tables, charts and exports use `buildReport`. No network or backend is simulated.

Simple products and each sellable variant own nullable `costPrice`, in whole toman. This is purchase price plus allocated direct acquisition costs, including inbound freight. Advertising, overhead, customer delivery and order packaging are excluded. Blank means unknown; explicit zero is valid for free/donated inventory. Variable parents have no cost field. Product editing and order creation share `productService`, the browser-local inventory repository and the React Query key.

`createOrderLines` captures both selling price and `unitCostSnapshot` when the order form is submitted, even for pending orders. Product changes, invoice-price edits, payment transitions and customer-information edits never refresh that snapshot. Local order persistence preserves it; missing historical snapshots load as null, without a catalog lookup. The previously explicit shirt/mug demo-ledger costs were moved to mock order lines. Bag and other unknown historical costs remain unknown. Newly created orders explicitly record zero line adjustments for independent line-level discounts/refunds; order-level percentage discounts are stored separately; absent legacy adjustment records remain unknown.

`demo-ledger.ts` now supplies only adjustments, two timestamped demo receipts and one packaging expense. Expense coverage, receipt coverage and historical cancellation coverage remain incomplete. New cancellation timestamps come from persisted orders; cancelled orders are excluded from sales, costs and profit without removing dated payment receipts. Product/variant names come from historical order lines, including Persian names in English UI. Variant quantities and costs are added once to the parent product; labels are displayed underneath it.

Sales use currently paid, non-cancelled orders **created** in the selected Tehran calendar dates, including both endpoints. Current statuses are not historical status snapshots. Pending orders are counted in analytics but excluded from sales. Item gross excludes shipping. Legacy discounts/refunds are total amounts per line, applied once to the creation cohort using currently recorded totals; this is not a refund cash-flow report. Order percentage discounts are computed by the shared order totals utility (0–100%, two decimal places, half-up whole-toman rounding) on products only, excluding shipping. Reports allocate that already-rounded amount across product/variant lines in stable order, carrying the rounding remainder forward, and deduct it once in addition to independent line adjustments. These allocations are derived, never written back into line adjustments. Gross stays pre-discount; net and profit use discounted revenue. Missing historical percentages mean zero and are not backfilled. Invoice snapshots capture the percentage at issuance and update with the order only during permitted unpaid edits. COGS uses historical unit cost times sold quantity, without assumed inventory returns. Inventory purchases do not also enter other expenses. Expense recognition uses occurredAt. Payments use confirmedAt, include any shipping collected, and are independent of order creation dates. A paid or sent invoice is never a dated receipt. Zero comparison baselines have no percentage. Missing purchase costs or expense coverage suppress estimated profit. Unrecorded adjustments leave net sales provisional, with a visible warning.

Cost coverage is **known-cost eligible quantity / all eligible sold quantity** (null if there are no eligible units). Explicit zero counts as known. `knownCost` sums only known snapshots. `cost` is null if any eligible cost is unknown; gross profit is net sales minus complete COGS and also requires complete adjustments. `profit` is estimated net profit: gross profit minus other expenses, available only with complete expense coverage. Known costs never masquerade as total COGS. Unknown expenses remain distinct from a complete zero-expense period. Inventory expense entries include inbound procurement costs and are excluded from other expenses to avoid deducting acquisition costs twice; the shipping expense category is customer delivery only. Refunds reduce revenue, but the domain has no returned-inventory quantity/cost-reversal events, so COGS is not automatically reversed.

Date presets use the same Persian calendar as the existing date picker in both languages. Current month ends today; today is partial. Comparison is the preceding equal number of calendar days, not elapsed hours. Daily buckets cover up to 45 days, seven-day buckets up to 180, then Persian calendar months with clipped endpoints. Custom ranges are limited to 3,660 days.

Laravel integration should replace `demoReportSource` with validated `ReportSource` data including stable order-line IDs (the MVP must use order ID + line index), immutable price/cost snapshots, item-allocated discounts/refunds, deduplicated confirmed payment events, cancellation timestamps, expense categories and explicit coverage guarantees. Monetary input is integer toman; averaging and percentages are rounded only for presentation. Unknown is distinct from zero. The adapter must validate nonnegative quantities/costs and adjustment bounds, deduplicate event IDs, and normalize timestamps. No endpoints are assumed.

CSV uses UTF-8 BOM, quoted fields and formula-prefix protection. ExcelJS is lazy-loaded to create real XLSX worksheets with numeric cells and RTL views. PDF is a browser print / Save as PDF fallback, using a separate print document with the application's fonts, localized text and RTL tables; it does not promise identical pagination across browsers. Exports include the exact selected report, comparison and coverage notes.

Run product validation, order snapshot/persistence/provider, calculation and export tests with `npx vitest run --project reports`.
